# OGL 商业级规范与设计自审（STANDARDS）

> 用途：①定义项目交付必须达到的商业级标准；②对架构设计做逐条自审，记录发现的问题与处置。

---

## 一、交付标准（十一条）

| # | 领域 | 标准要求 |
|---|---|---|
| S1 | 代码规范 | Effective Dart；分层 / 依赖规则由脚本与 CI 强制；公共 API 文档注释 100%；单文件建议 ≤400 行；禁止魔术数字 |
| S2 | 错误处理 | 统一异常层次（传输 / 领域 / 交互 / 界面）；用户可读消息与开发者诊断分离；**禁止吞异常**；所有外部输入边界兜底 |
| S3 | 日志与可观测 | 分级日志 + 结构化字段 + 敏感信息脱敏；一致性审计日志（见 CONSISTENCY 第 7 节）；发布版可整体关闭调试日志 |
| S4 | 安全 | 令牌仅存安全保险库；日志 / 崩溃报告中密钥零出现；依赖锁定与漏洞审计；Mod / 主题包**无代码执行**；更新包校验（哈希 / 签名） |
| S5 | 性能预算 | 冷启动 ≤2.5s（中端机）；文件列表滚动 60fps；内存常驻 ≤200MB 量级；网络并发上限受控；安装包体积目标 ≤60MB |
| S6 | 测试与门禁 | 底座 + API 核心单测覆盖 ≥80%；一致性协议测试（CONSISTENCY §8）与启动层测试（BOOT §7）必过；CI 未过禁止合入 |
| S7 | 文档 | 架构 / 协议文档先行；模块 README；CHANGELOG；关键决策记录 ADR；用户可见的更新说明 |
| S8 | 兼容性 | Android minSdk22（5.1）→ 最新；Windows / Linux 双击即用；JSON 协议 schema 版本化 + extra 冗余 + 缺省继承 |
| S9 | 发布 | 语义化版本；产物签名 + SHA256SUMS；更新协议支持增量与回滚；Release Notes 结构化 |
| S10 | 流程 | 变更走分支 / PR；PR 模板含审查清单；破坏性变更必须 ADR + 迁移说明 |
| S11 | 供应链完整性 | 引导清单（boot manifest）随构建生成（CI 强制）；官方模块指纹校验（BL 锁）；第三方主题开放 / Mod 警告策略；校验失败进安全模式 |

## 二、设计自审报告

> 审查对象：v2 架构设计 · 结论：**不通过**，共发现 7 项问题（含 1 项致命），已在 v3 / v3.1 修复。

| # | 级别 | 发现的问题 | 处置 |
|---|---|---|---|
| A1 | 高 | 缺少模块引入与生命周期治理机制，模块间装配靠"手工 new"，无法保证初始化顺序与失败回滚 | **新增总线段（Kernel）**：模块引入 / DI / 拓扑初始化 / 桥发现 / 启动诊断 |
| A2 | 高 | 层间边界只有文字约定，无强制手段；跨层直连内部实现不可避免 | **每层新增桥模块**：跨层仅允许走桥；依赖规则可脚本强制检查 |
| A3 | **致命** | 缓存设计仅做到"介质与策略分离"，未定义一致性等级、作用域隔离与**防错位覆盖协议**——对代码仓库是致命缺陷 | **新增 CONSISTENCY.md 协议**：单一事实源原则 + 七道防线（D1-D7）+ 作用域键 + schema 版本 + 审计日志 + 测试门禁 |
| A4 | 中 | 无审计与可观测性规范，冲突 / 重试 / 失效不可复盘 | CONSISTENCY §7 审计日志字段规范；Kernel 启动诊断 |
| A5 | 中 | 扩展体系（Mod / 主题包）缺版本协商与回滚机制 | schema 版本协商 + 引擎版本声明 + 违规包禁用与回滚 |
| A6 | 中 | 无性能预算，后期无法判定"是否达标" | 新增 S5 性能预算（启动 / 滚动 / 内存 / 包体） |
| A7 | 低 | 缺变更流程与决策记录（ADR），团队协作与演进将无据可依 | 新增 S10 流程规范 + S7 ADR 要求 |

**复核结论**：v3.1 设计已覆盖全部 7 项问题的修复路径；其中 A3（缓存一致性）与启动层信任策略为强制验收项，将在 M1 阶段连同测试用例一并实现验真。

## 三、代码评审清单（PR 必查）

- [ ] 是否触碰了 CONSISTENCY 禁止清单（绕过冲突治理 / 盲写 / 乐观更新冒充回读 / 跨作用域缓存）？
- [ ] 跨层引用是否只 import 了对方 bridge？
- [ ] 新增模块是否在 Kernel 里声明了依赖与生命周期？
- [ ] 新增 / 改动模块是否更新了引导清单（boot manifest）与指纹？
- [ ] 是否遵守信任策略（官方 locked / 主题 open / Mod warn + 总线警告）？
- [ ] 外部输入是否全部容错解析（未知字段保留、缺字段默认）？
- [ ] 敏感数据是否只进 secret_vault？日志是否脱敏？
- [ ] 是否有对应测试？核心路径覆盖率是否达标？
- [ ] 用户可见文案是否可读（中文 / 英文）？错误是否有下一步指引？
- [ ] 危险操作是否有二次确认与审计日志？
- [ ] 是否更新了文档（架构 / 协议 / BOOT / CHANGELOG / ADR）？
