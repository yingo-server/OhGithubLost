## 1. 分层修复原则

```
L0 内核    不动（信任链已固化）
L1 底座    存储接线 / 失败上报 /（检查）装配测试
L2 领域    解码修复 /（检查）解码测试
L3 表面    S1 组件导航 → S2 页面结构 → S3 图标体系 → S4 Primer 细节
工程        CI / 构建 / 发布 / 证书 / 文档
```

每题都遵守：**根因 → 修复 → 检查（测试或 CI 护栏）→ 推送**。

## 3. 推送策略（硬性）

1. 每层收口 **一次** push（代码 + 检查 + 文档 同批）；
2. push 前必须：本地核查新增 API 的引用点全部对齐（编译级自查）；
3. push 后等 **CI 绿** 才进下一层；CI 红则修复后重推同一层；
4. 构建（build.yml）随 push 自动跑，13 目标必须全绿（best_effort 记档）。
