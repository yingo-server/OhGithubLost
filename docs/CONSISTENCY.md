# OGL 缓存与一致性协议（CONSISTENCY）

> 定位：**代码仓库应用的致命区**。版本不一致、错位覆盖（stale overwrite）会造成用户代码丢失——本协议按"不可妥协"级别设计与验收。

---

## 1. 风险模型（先定义敌人）

| # | 风险场景 | 后果 |
|---|---|---|
| R1 | 用过期 SHA 写入 →覆盖掉别人/其他设备的新提交 | **代码丢失（致命）** |
| R2 | 缓存串账号：A 账号的目录列表被 B 账号读写 | 越权/错乱 |
| R3 | 缓存串分支：切分支后仍显示旧分支文件 | 错位操作 |
| R4 | 本机并发写：两个任务同时改同一路径，互相踩踏 | 覆盖/丢失 |
| R5 | 应用升级后缓存结构变化，旧缓存被当新数据用 | 解析错误/破坏 |
| R6 | 任务乱序：先完成的"删除"被后完成的"上传"结果覆盖 | 状态错乱 |
| R7 | 写成功但界面/缓存未刷新，用户基于旧视图再次操作 | 二次错误 |

## 2. 第一原则：单一事实源

> **GitHub 是唯一事实源；本地一切缓存都是"可能过期的副本"。**

由此推出：
- 任何**写操作前必须核验**（read-verify-write），禁止"凭本地 SHA 盲写"；
- 任何**写操作后必须回读确认**，乐观 UI 只是显示层，不得作为数据结论；
- 无法确认一致性时，**宁可不写、不删、不覆盖**，转为明确提示用户。

## 3. 缓存架构（三层 + 元数据）

| 层 | 范围 | 说明 |
|---|---|---|
| L0 内存 | 会话级 | 当前视图数据；随会话/仓库切换销毁 |
| L1 磁盘 | 持久级 | 块存储；带淘汰；跨启动复用 |
| L2 远端 | 事实源 | 经 ETag 条件请求（304 快路径） |

**每条缓存必须携带元数据**：
`etag · sha · fetchedAt · schemaVersion · scope(accountId/repo/branch) · origin(api/raw)`

**缓存键作用域（防串味，对应 R2/R3）**：
```
key = schemaVersion | accountId | repo | branch | path
```
- 切换账号 / 分支 / 仓库 → **切换命名空间**，禁止跨命名空间命中；
- 命名空间不匹配 → 视为未命中（不是"尝试兼容"）。

## 4. 写入一致性协议（七道防线）

| 防线 | 机制 | 对应风险 |
|---|---|---|
| **D1 写前必读** | 写入前实时获取当前 SHA/版本（走缓存也必须 revalidate） | R1 |
| **D2 SHA 乐观锁** | 携带实时 SHA 提交（GitHub 原生并发机制） | R1 |
| **D3 冲突自动重试** | 409/422 →重取 SHA →有限次重试（3 次，指数退避），每次冲突全记录 | R1/R4 |
| **D4 本地写队列串行化** | 以 `repo+path` 为粒度排队，同粒度写任务串行执行 | R4/R6 |
| **D5 写后失效 +回读** | 成功后立即：失效该路径及父路径缓存 →重新拉取 →确认服务器状态=预期 | R7 |
| **D6 失败可感知** | 自动重试仍失败 →**明确冲突提示**（展示双方版本信息），绝不静默覆盖 | R1 |
| **D7 危险操作二次确认** | 删除/批量删除/批量发布/强制覆盖 →二次确认 +操作日志 | R1/R7 |

**禁止清单（代码评审红线）**：
- ❌ 任何绕过 `conflict_guard` 的写调用；
- ❌ 用缓存中的 SHA 直接 PUT（必须 D1 重取）；
- ❌ 写成功后仅做"乐观更新"而不回读；
- ❌ 在无 scope 校验的情况下复用缓存条目。

## 5. 一致性等级（按数据性质分级，不做"一刀切"）

| 数据类型 | 等级 | 策略 |
|---|---|---|
| 文件内容 / 目录列表 | **强一致** | 写后失效+回读；进入目录时 revalidate |
| 分支列表 / 仓库元信息 | 准强一致 | 短 TTL +关键操作前强制刷新 |
| 仓库列表 / star 数 / 计数类 | 弱一致 | TTL 分级 +下拉刷新；允许短暂过期 |
| 限流快照 / 网络状态 | 实时 | 不进缓存，事件驱动 |
| 任务日志 | 只追加 | 不做失效 |

## 6. 版本一致性（跨应用版本 / 跨设备）

- **schemaVersion**：缓存结构变更时自增；命中时校验不符 →**整片丢弃**（对应 R5，禁止"尽力解析"）；
- 应用升级：首次启动执行缓存迁移或清理策略（迁移必须可回滚、可跳过）；
- 跨设备：**永不信任**其他设备产生的缓存（缓存不共享、不导入导出）；进入仓库时按需 revalidate。

## 7. 可观测性（审计要求）

所有一致性相关事件输出**结构化审计日志**（本地滚动，可导出）：
```
ts · actor(account) · repo · branch · path · op · attempt · reason(409/etag-miss/schema-mismatch/queue) · result
```
用途：冲突复盘、用户申诉、回归定位。

## 8. 测试要求（CI 门禁）

一致性协议必须有针对性测试，未通过不允许合入：
1. 写-写竞争：模拟另一客户端抢先提交 →验证 D2/D3/D5 行为；
2. 冲突上限：连续冲突超限 →验证 D6 提示而非覆盖；
3. 作用域隔离：跨账号/跨分支/跨仓库取缓存 →必须未命中；
4. schema 失配：伪造旧 schemaVersion 缓存 →必须被丢弃；
5. 队列串行化：并发发起同路径写 →验证串行与最终一致；
6. 写后回读：模拟回读失败 →任务标记失败，不得报成功。

## 9. 与架构的落点

| 协议要素 | 归属模块 |
|---|---|
| 缓存介质与元数据 | `base/disk/blob_cache` |
| 条件请求（ETag/304） | `base/net/net_engine` |
| 冲突治理（D1-D3） | `domain/api/conflict_guard` |
| 缓存策略/失效清单/等级 | `domain/api/cache_policy` |
| 写队列串行化（D4） | `domain/interaction/tasks` |
| 提示与确认（D6/D7） | `surface/ui`（经交互层命令） |
| 审计日志 | `build-in`：kernel 诊断 + disk 日志 |

---
*本协议为强制性验收标准：涉及仓库读写的任何功能，实现与评审都必须逐条对照本文。*
