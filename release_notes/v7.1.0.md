# OhGithubLost v7.1.0

**Web 版与原生版拆成两个独立系统。** 本分支（main）回归纯原生：Android / Windows / Linux。
Web 版在自己的分支上独立维护与发布，不产生 GitHub Release。
Web and native are now two independent systems; this branch is native-only
(Android / Windows / Linux). The web build lives on its own branch.

## 变更 / Changed

- **移除本分支上的全部 Web 支持**：
  - 条件导入（`import 'x_io.dart' if (dart.library.js_interop) 'x_web.dart';`）
    改回直接导入；删除全部 `*_web.dart` 实现；
  - 删除 `web/` 脚手架与 `.github/workflows/web.yml`；
  - 移除仅为 Web 引入的 `http` 依赖；
  - 清除界面上的 Web 专属入口（设置页的 Web 分区、安装提示接线、浏览器权限与通知网关）
    及对应文案键（6 个语言同步删除）。

  为什么拆：两端在**磁盘与网络这两层的能力并不等价** —— 浏览器没有文件系统
  （文件类存储仅会话内有效、令牌只能内存持有）、没有裸 socket（自定义 DNS / DoH 不可用）、
  下载要交给浏览器（暂停 / 续传 / 分片 / 校验都不可用）。
  留在同一条发布线上，会让「一份代码全平台」看起来成立，实际混着两套能力边界。
  拆开后，本分支的构建与测试只面对原生语义。

## 修复 / Fixed

收入 v6.5.0 之后、未随任何版本发布过的三条收尾修复：

- **完整性校验不匹配时删除落盘文件**。此前坏文件留在原处，用户点「重试」只会把
  同一份字节再校验一遍，永远失败。
- **启动信任链如实报告**：清单未声明模块条目时，阶段详情写明「本阶段无校验对象」，
  而不是显示「0 个模块通过」—— 后者会被读成「模块完整性已校验」。
  实际原因是核心模块为 AOT 产物，没有可指纹化的目录文件。
- **16 处悬空文档引用逐处标注**「该文件未落地，以源码为准」（涉及 13 个文件）。

## 已知限制 / Known limitations

- Web 版不在本分支：它在独立分支维护，产物发布到该分支的 `app/<纯数字版本>/`
  （如 `710`），入口页用 iframe 指向最新版本，且不产生 GitHub Release。
- `docs/ARCHITECTURE.md` 等 5 份被注释引用的文档仍不存在（已逐处标注）。
- 镜像机制、仅测试使用的 `ScriptedTransport`、无调用方的 `DiskPaths` 只加注说明，未删除。
- **Linux 裸放安装包 3 / 6**：rpm（arm64）缺平台定义；AppImage 的 `ARCH`
  环境变量未被接受。三种包在 zip / 7z 里都齐全。
- macOS / iOS 原生应用自 v5.6.0 起弃用。
